# Прогресс

## Этап 1: сборщики Lidl / Kaufland / BILLA -> SQLite -> JSON (готов)

Сделано:
- адаптеры трёх сетей и единая модель Offer / PriceCondition (цены в центах EUR, виды regular/promo/loyalty/multibuy);
- Kaufland: скидки на бренд целиком получают осмысленное название; акции 1+1 / 2+1 сохраняются как multibuy;
- SQLite: products, offers, offer_prices, price_observations (история), scrape_runs (content_hash/content_changed);
- пайплайн: блокировка, слоты расписания (Europe/Sofia, без зависимости от TZ хоста), архив сырых ответов с ротацией, проверки полноты, подозрительный запуск не перезаписывает данные;
- JSON-экспорт (атомарная запись), признак stale по сетям;
- CLI: collect / export / stats;
- Docker: Dockerfile, docker-compose.yml (запуск из cron на хосте);
- README (EN/RU), QUICK_START, SOURCES.

Проверено:
- 83 теста pytest проходят;
- живой прогон 2026-10-17: Lidl 282 акции, Kaufland 2079 предложений (71 multibuy), BILLA 278;
- сбор Kaufland после правок: 0 названий, начинающихся с «-».

Известные ограничения:
- BILLA: названия - свободный текст, изображений нет; источник запрещён в robots.txt (используется по решению владельца);
- Kaufland: скидки на бренд целиком не относятся к одному товару;
- Lidl: API покрывает онлайн-ассортимент, позиции только из листовки могут отсутствовать;
- нет сопоставления товаров между сетями;
- сборка образа Docker не проверялась локально (Docker на машине разработки отсутствует).

Кандидаты следующих этапов (не начаты):
- сопоставление товаров между сетями (бренд, объём, нормализация названий);
- расчёт цены за единицу (кг/л) и сравнение цен;
- сервис/интерфейс поверх JSON/SQLite;
- уведомления о смене цен.
